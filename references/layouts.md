# 版式

排版前读。版式在模板的基础上排：SKILL.md 第 2 节的配色、字号，网格对齐，卡片标题条，每页成块的主色，这些基础照常遵守。
这里讲在这个基础上怎么按内容安排一页：除了标「用户明确要求过」的偏好，都是判断方法和例子，按内容取舍和组合。

## 1. 用户的偏好和背后的原因

- **在模板基础上排，基础不能丢**（用户明确要求过）：文字和表格放进带标题条的卡片或浅色底块，有标题、有边界；
  把卡片都拿掉、表格光秃秃摆在白底上，看着像没做完，用户评价「还不如之前的模板」。
  死板的不是卡片本身，而是每页都是同样几张卡片铺满、图被缩成卡片里的小缩略图。
- **页面靠真实的图说服人**（用户明确要求过）：听众信的是实验图、数据图、仪器照片、文献原图。
  有图的页让图当主角、放够大（直接放在正文区，或放在卡片里但占卡片大半），解读写在旁边的卡片里。
- **能用照片就不用方框**（用户明确要求过）：器件、部件、设备、历史事件都先找真实照片（`figures.md` 第 3 节），
  步骤和时间线的节点也配照片；方框和原生示意只留给拍不出来的东西。
- **不做方框流程页**（用户评价「丑死了」）：讲方法、研究内容、方案时，不用一排排 `node()` 小方框加箭头拼整页流程图，
  用实验图、仿真图、文献先例图配表格或要点写清做法。作者自己画的框架图直接嵌入，不重画。
  `node()` 只用在知识关系图这类本身就是节点图的地方。
- **几项并列的图片页不做等宽卡片阵列**（用户评价「布局太死板」）：研究现状这类每项都有原文图的页，
  每项一张带标题栏的卡片等宽排开，图都缩得很小。用第 6 节的做法，图直接排开，靠留白和细线分组。
- **内容充实指信息量**（用户明确要求过）：证据要能证明标题，原因、数字、例子写足；不是把正文区每一寸填满。
  往卡片里堆要点不算充实；十二个小方框各写一个词，填满了也是空的。

## 2. 设计一页：先想三件事，再选容器

1. **主角**：这一页要听众第一眼看到什么——一张图、一个数字、一组对比、一句判断。
   主角给最大的面积和最好的位置（通常是左上到中间），其余缩小、放到旁边，或者调淡。几样东西分量相同时，先怀疑是不是该拆页。
2. **阅读路径**：内容自己的结构决定怎么摆。
   流程从左到右、箭头顺着读序；对比左右或上下对照，两边同尺寸、同位置；总分是一张大图加局部放大或引线标注；
   并列只在确实同等重要时等分；层级是一大几小。
3. **材料的形状**：宽图横放占满宽度，文字放上下；竖图放一侧，文字放另一侧；组图整组放，不拆开重排；
   分辨率低的图不放大。很多时候图的宽高比已经决定了版面怎么切。

想清楚之后再定块的大小和位置：主角给最大的块，图可以直接放在正文区，也可以放在卡片里，但要够大；
文字和表格放进带标题条的卡片或浅色底块（`tint()`）；每页至少一处成块的主色，强调色只给关键数字和结论。

## 3. 判断好坏

排完看渲染图，逐条问：

| 问题 | 不好的样子 |
|---|---|
| 主角一眼可见？ | 几块分量相同，不知道先看哪 |
| 图够大、看得清？ | 图被框在卡片里只占页面四分之一，图上的字看不清 |
| 视线路径顺？ | 要来回跳着看；箭头逆着读序 |
| 留白成组？ | 留白是零碎的缝；或者每一寸都塞满，没有喘气的地方 |
| 每个元素都有用？ | 重复的标签、只有一两个词的卡片 |
| 像做完了？ | 表格、文字光秃秃摆在白底上，没有标题和边界 |
| 和前后页有变化？ | 连续几页同一种结构，只是块的位置略有不同 |

## 4. 整份的节奏

- **翻页要有轻重**：信息密的页（对比表、多图对照）之间，穿插轻的页——一张大图配一句话、一个关键数字、一张引出问题的照片。
  每页都一样密，听众翻几页就累了。
- **页计划里的「构图」一列连着读**：看是不是每页都同一种语法（比如全是标题栏卡片铺满正文区）。
  大多数页都是卡片铺满时 `qa_check.py` 会报 ⚠️；同一构图（块的位置和尺寸）出现 5 页以上也会报。
- 同一种做法连续不超过三四页；章节内部可以有自己的固定结构，但章与章之间要换。
- 第 7 节的命名页型结构差别大，适合拿来打破「每页都是卡片铺满」：页计划的「构图」一列直接写页型名，
  内容合适时用上；同一种命名页型不连排两页。

## 5. 细节

- **对齐**：该对齐的边完全对齐，不该对齐的明显拉开；差 0.1cm 的「差一点对齐」最难看，`qa_check.py` 会报近似错位。
  几列图要逐行对齐时，每行用一个 `strip()` 定死行高，不要每列一个 `gallery()`（它按宽高比排，各列第二行的上沿会差几毫米）。
- **结果页**：主图占正文区 60–75%，旁边一条窄解释栏或底部一句结论；左右等分只用于两件东西确实要对比。
- **同一页不把同一件事讲两遍**：流程图每一步的作用直接写在那一步旁边，不在下面再排一行同名卡片。
- **关键数字单独拿出来**：要听众记住的两三个数字用 `keynum()` 放大，对齐在它所属的那一步、那一列，不埋在条目里。
- **短语按意群手动分行**：窄栏里的说明写成两段（`["一段短金属管", "把微波送进炉腔"]`），不让自动换行把词拆开。
  标签先算「栏宽 ÷ 0.564cm」得出 16pt 一行能放几个字。
- **卡片**：数量跟着内容走，不凑整；主次用大小区分，不要每页都是几张等大的卡片；卡片里不留大块空白，空了就缩小卡片。
- **坐标**：块用 `Grid` 网格对齐（`g = Grid()`，`g.box(列, 行, 占几列, 占几行)`）；一块区域里拼几张图时用
  `strip()` / `gallery()` 按宽高比（`aspect(图)`）算尺寸。只有第 6 节那类几项并列的图片页，才从正文区
  `B = Grid().box(0, 0, 12, 6)` 起按图的形状排（华科模板宽 29.8cm、高 12.2cm）。

几种常见构图，按内容选用或组合：

| 切法 | 网格 | 适合 |
|---|---|---|
| 图为主 | `g.box(0,0,8,6)` + `g.box(8,0,4,6)` | 结果页：一张主图 + 解读 |
| 上宽下格 | `g.box(0,0,12,2)` + 下方 `g.box(4*i,2,4,4)` | 一个结论或路线 + 几条支撑 |
| 主次结合 | `g.box(0,0,3,6)` + `g.box(3,0,6,6)` + `g.box(9,0,3,6)` | 中间核心机制，两侧输入和输出 |
| 便当混合 | 如 `g.box(0,0,7,6)` + `g.box(7,0,5,3)` + `g.box(7,3,5,3)` | 一个主角 + 两个配角，大小不等 |
| 流程 + 数字带 | `g.box(0,0,12,4)` + `g.box(0,4,12,2)` | 步骤在上，关键数字对齐在下 |
| 全宽 | `g.box(0,0,12,6)` | 表格、图表、节点图、一张大图 |
| 左右对比 | `g.box(0,0,6,6)` + `g.box(6,0,6,6)` | 两件东西确实要对比 |

## 6. 例子：几项并列、每项都有图的页

研究现状（几篇文献）、方法对比、几种器件或现象：每项都有图，要讲清各自的「对象 → 方法 → 结果」。
下面五种做法各解决一个具体问题，是用户对照多种方案后觉得可用的（参考了 Stanford CS231n 2025 第 9 讲、
Gómez Bruballa 博士答辩 gombru.github.io/phd_defence、中科院等离子体所介绍材料）。
它们是例子，不是菜单：新内容先按第 2 节想，结果可能是其中一种、两种的组合，或者全新的排法。
`examples/layouts/build_deck.py` 用 Wikimedia Commons 的放电照片把它们各做了一页。

| 做法 | 解决的问题 | 不适合 |
|---|---|---|
| A 并列多列 | 3–4 项同等重要、图的形状各不相同 | 5 项以上（列太窄） |
| B 每行一项 | 每项都分得出「输入」和「结果」，要读出从左到右的过程 | 又高又窄的图（放进一行太小） |
| C 图片表格 | 几项按同样的维度比较，横着看差别 | 每项只有一张合成图，拆不成行 |
| E 大图 + 引线标注 | 一张图里有几处要分别讲 | 图上没有可指的细节 |
| F 一大几小 | 有一项要重点讲（和本课题最接近） | 几项确实同等重要 |

每项的文字分三层：标签 16pt 粗体主色；方法或目标 13pt；出处 13pt 灰色，写「作者 et al., 年份」，窄栏拆成两行，
文献号和文末参考文献一致（组会、课程汇报按 SKILL.md 第 3 节，页面上不写出处）。
同一行的图等高、上沿对齐，图注一行写图里是什么。原文里的关键数字用强调色粗体，一页最多一两个。
图取自已有的 PPT 或报告时组图照原样放；自己从论文取图时按 `figures.md` 第 4 节裁到子图。

下面的代码是骨架，尺寸都由图的宽高比算出，排完看渲染图再调。假定 `B = Grid().box(0, 0, 12, 6)`、
`PRI = TONES["primary"].base`，每项的数据写成字典：

```python
items = [
    dict(tag="[1] 推力器羽流", method="卷积神经网络", target="诊断电子温度、密度",
         src=["哈尔滨工业大学", "学位论文, 2020"],                           # 一行一段；宽栏可合成一行
         arrow=["卷积神经网络"],                                              # B 用：箭头上的方法，按意群分行
         inp=[([FIG / "plume.png"], "霍尔推力器羽流")],                      # B、C 用：输入图分组和图注
         out=[([FIG / "te_map.png", FIG / "ne_map.png"], "诊断出的参数分布")],  # B、C 用：结果图
         rows=[[FIG / "plume.png"], [FIG / "te_map.png", FIG / "ne_map.png"]],  # A、F 用：gallery 的行
         res=["羽流图像 + 卷积神经网络", "诊断电子温度、电子密度"]),
    dict(tag="[4] 火花放电", ...,
         res=["亮度与电流线性相关", P(R("R² = 0.97", bold=True, color=TONES["accent"].ink)), "可推算分支电流"]),
]


def head(c, box, it, align="c"):
    """一项的标题块：标签、方法、出处。"""
    c.text(box, [P(R(it["tag"], bold=True, color=PRI, size=S_BODY)), P(R(it["method"], size=S_SMALL), before=4)]
           + [P(R(s, size=S_SMALL, color=GRAY), before=2) for s in it["src"]], align=align)


def head_h(its):
    """标题块高度：标签 0.75cm + 方法和出处每行 0.6cm，取几项中最高的，各项的图才能上沿对齐。"""
    return 0.75 + 0.6 * (1 + max(len(it["src"]) for it in its))


def share(widths_needed, total, gap):
    """按各栏需要的相对宽度分配 total（扣掉栏间距），返回各栏宽度。"""
    room = total - gap * (len(widths_needed) - 1)
    return [room * w / sum(widths_needed) for w in widths_needed]
```

出处两行时标题块是四行（约 2.6cm），图的上沿一律放在 `B.t - head_h(...) - 0.3`，否则会压到图上（`qa_check.py` 报文字压图）。

### A 并列多列

每项一列：标题块 → 图 → 两三行结论，三者各自对齐成一条线；列之间一条细竖线。
列宽按每列图的宽高比分配；某列算出来比标签还窄时，手动给它让一点宽度。

```python
gap = 1.0
widths = share([max(sum(aspect(p) for p in row) for row in it["rows"]) + 1.0 for it in items], B.w, gap)
hh, x = head_h(items), B.l
for k, (w, it) in enumerate(zip(widths, items)):
    head(c, Box(x, B.t, w, hh), it)
    c.gallery(Box(x, B.t - hh - 0.3, w, 8.9 - hh), it["rows"], valign="n")   # 各列图的上沿对齐
    c.text(Box(x, B.t - 9.5, w, 2.6), it["res"], size=S_BODY, align="c", line=26)
    if k < len(items) - 1:
        c.line((x + w + gap / 2, B.t), (x + w + gap / 2, B.t - 12.0), LINE, 0.75)
    x += w + gap
```

### B 每行一项：输入图 → 方法 → 结果图

每行从左读到右：左栏写标签、目标和出处，输入图贴住箭头，箭头上写方法，右边结果图。
各行的箭头在同一列，输入图右边、结果图左边都上下对齐；行间一条细横线。
图高由最宽的一行决定；方法写在箭头上方，13pt，一行不超过 6 个字。

```python
left, arrow_w, cap_h = 4.6, 3.0, 0.7
n = len(items)
a_in = [sum(aspect(p) for g in it["inp"] for p in g[0]) for it in items]   # 各行输入图、结果图排开的宽高比之和
a_out = [sum(aspect(p) for g in it["out"] for p in g[0]) for it in items]
H = min((B.h - 0.8 * (n - 1)) / n - cap_h, (B.w - left - 0.3 - arrow_w - 1.2) / max(i + o for i, o in zip(a_in, a_out)))
x_in = B.l + left + 0.3 + H * max(a_in) + 0.6        # 输入图右边、结果图左边，箭头在两者之间
x_out = x_in + arrow_w
pitch = (B.h - H - cap_h) / (n - 1)                  # 各行上下占满正文区
for i, it in enumerate(items):
    y = B.t - i * pitch
    c.text(Box(B.l, y, left, H), [P(R(it["tag"], size=S_BODY, bold=True, color=PRI)), P(it["target"], before=4)]
           + [P(R(s, color=GRAY), before=6 if j == 0 else 0) for j, s in enumerate(it["src"])],
           size=S_SMALL, anchor="m")
    c.strip(Box(B.l + left + 0.3, y, x_in - B.l - left - 0.3, H + cap_h), it["inp"], ggap=0.3, align="e")
    c.strip(Box(x_out, y, B.r - x_out, H + cap_h), it["out"], ggap=0.3, align="w")
    mid = y - H / 2
    c.line((x_in + 0.3, mid), (x_out - 0.3, mid), PRI, 1.5, arrow=True)
    c.at("s", (x_in + x_out) / 2, mid + 0.15, it["arrow"], size=S_SMALL, color=INK)
    if i < n - 1:
        c.line((B.l, y - (pitch + H + cap_h) / 2), (B.r, y - (pitch + H + cap_h) / 2), LINE, 0.75)
```

四项、图形状差别大时排不成行，可以改成 2×2 四格：每格一边文字、一边 `gallery()`，中间一横一竖两条细线。

### C 图片表格

列是各项，行是比较的维度（输入 / 结果，或不同条件）；左边一窄栏写行名，每格用 `strip()` 把图放进格子，
同一行的图上沿对齐；表头下、行间各一条细横线，列间细竖线。

```python
lab_w, hh, keys = 1.5, head_h(items), ["inp", "out"]
widths = share([max(sum(aspect(p) for g in it[k] for p in g[0]) for k in keys) for it in items], B.w - lab_w - 0.3, 0.6)
rh = (B.h - hh - 0.3) / len(keys)
x = B.l + lab_w + 0.3
for i, (w, it) in enumerate(zip(widths, items)):
    head(c, Box(x, B.t, w, hh), it)
    for r, key in enumerate(keys):
        c.strip(Box(x, B.t - hh - 0.3 - r * rh, w, rh - 0.2), it[key], ggap=0.25, valign="n")
    if i < len(items) - 1:
        c.line((x + w + 0.3, B.t), (x + w + 0.3, B.b), LINE, 0.75)
    x += w + 0.6
for r, name in enumerate([["放电", "图像"], ["诊断", "结果"]]):
    y = B.t - hh - 0.3 - r * rh
    c.text(Box(B.l, y, lab_w, rh), [P(R(t, bold=True, color=INK)) for t in name], anchor="m")
    c.line((B.l, y + 0.15), (B.r, y + 0.15), LINE, 0.75)
```

### E 大图 + 引线标注

一张图占满大半页，要讲的几处用主色细线引到图外，引线末端写一两句说明；说明排在图的一侧或两侧，上下对齐。
适合「这张图里有几个地方值得看」：放电管的分段、装置上的诊断窗口、器件剖面的各层。
标注只写图上看得到的东西；点位按图的比例给（如「右段约 0.6–0.95 宽处」），换图时重新量。
`examples/layouts/build_deck.py` 的 E 页是一个完整写法；说明放进两侧浅底块的做法见第 7 节「引线标注」。

### F 一大几小

挑一项放大（和本课题做法最接近、或要重点讲的），占左边四成左右；其余几项缩小放在右边，
排成几列或上下几行。为什么放大这一项写进口播稿。

```python
main, others = items[2], [items[0], items[1], items[3]]
main_w = B.w * 0.42
hh = head_h([main])
head(c, Box(B.l, B.t, main_w, hh), main, align="l")
c.gallery(Box(B.l, B.t - hh - 0.3, main_w, 9.0 - hh), main["rows"], valign="n")
c.text(Box(B.l, B.t - 9.4, main_w, 2.8), main["res"], size=S_BODY, line=26)
x0 = B.l + main_w + 1.2
c.line((x0 - 0.6, B.t), (x0 - 0.6, B.b), LINE, 0.75)
w = (B.r - x0 - 0.6 * (len(others) - 1)) / len(others)
for k, it in enumerate(others):
    x = x0 + k * (w + 0.6)
    c.text(Box(x, B.t, w, 1.4), [P(R(it["tag"], bold=True, color=PRI)), P(R(it["method"], size=S_SMALL), before=4)],
           align="c")
    c.gallery(Box(x, B.t - 1.6, w, 6.6), it["rows"], valign="n")
    c.text(Box(x, B.t - 8.5, w, 3.6), it["res"] + [P(R(s, color=GRAY), before=6 if j == 0 else 0)
                                                    for j, s in enumerate(it["src"])], size=S_SMALL, align="c", line=20)
```

## 7. 命名页型

下面四种页型结构各不相同，用户看过试做后认可。和第 5 节的网格切法不同，它们改的是页面的结构本身，
不只是卡片的大小和比例；顶栏、标题、配色、成块主色这些基础照常。完整代码在 `examples/microwave/build_deck.py`，
按注释里的页型名找。

| 页型 | 适合 | 示例页 |
|---|---|---|
| 时间线 | 发展历程、研究进展、项目阶段 | 微波炉的来历（1940–1970s） |
| 引线标注 | 器件结构、实验装置、软件界面：一张图里有几处要分别讲 | 磁控管的六个部件 |
| 大序号步骤 | 流程、方法步骤、能量或数据的路径 | 市电到炉腔的五步 |
| 公式拆解 | 一页只讲一个核心公式，每一项都要解释 | 介质加热功率公式 |

### 时间线

- 一条主色横轴贯穿页宽（`line(..., TONES["primary"].base, 2.5, arrow=True)`），节点 5–6 个，间距 = 29.8 ÷ 节点数。
- 年份 `S_MARK` 粗体放在轴上方，事件两行 16pt 粗体放在轴下方，细节两行 13pt 灰色；每行按意群手动分好（4.8cm 宽一行约 8 个字）。
- 节点上方放当年的实物照片，用 `web_figure(..., fill=True)` 裁成同样大小；没有照片的关键节点放同样大小的强调色底块，写一句经过。
- 关键节点（转折、发现）用强调色，圆点放大；下面一条实色主色带写这段历史说明了什么，右侧放一个跨度数字。

### 引线标注

- 图居中占正文区一半（`Grid(bottombar=True).box(3, 0, 6, 6)`，`align="n"` 上沿和两侧块对齐），说明分在左右两栏的浅底块里
  （`box(0, 2k, 3, 2)` 和 `box(9, 2k, 3, 2)`），每块：序号 + 部件名 + 两行说明。
- 引线从块的标题行引到图上的部位，终点画一个强调色空心圆；终点用 `on_image(pic, 图, px, py)` 由原图像素坐标算出，像素坐标看图量。
- 按终点在图上的高低给块排序，左栏指左半边、右栏指右半边，引线不交叉。图上自带编号时，块的序号就用图上的编号。
- 工作过程按编号讲，类比和补充原理放 `bottombar()`。

### 大序号步骤

- 正文区上部按步骤数等分成列（`Grid(cols=5).box(i, 0, 1, 4)`），每列：`S_DISPLAY` 序号 → 实物照片（`fill=True`，同样大小）
  → 18pt 步骤名 → 两行说明；序号之间用主色箭头连起来。不画节点方框。
- 关键一步整列加强调色底（`tint(col, "accent")`），序号和说明也用强调色。
- 下面两行网格放这条路径的补充：一块浅底写对比或选择理由，一块强调色底放关键数字。

### 公式拆解

- 公式各项用 `at()` 分开放在一行（`S_DISPLAY`），每一项正好在下面一块的正中，中间放 = 和 ·；每项向下一条箭头指到它的解释块
  （`Grid(cols=5, bottombar=True).box(i, 2, 1, 4)`，项多就增减列数）。
- 等号左边的结果项用实色主色块，关键项用强调色浅底，其余主色浅底；每块：名称 → 三行解释 → 细线 → 一句结论（13pt 粗体）。
- 定性的机制（分子怎么转、为什么生热）写进对应项的解释和口播稿，常见误区放 `bottombar()`。
