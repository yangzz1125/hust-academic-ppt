# 学术汇报的内容规范

写页计划前读一遍。改已有 deck 时，把第 2–4 节当检查清单。

## 1. 论证主线

先确定整份汇报要让听众接受的那**一个**结论，其余内容都为它服务。讲不完的放进备注或备用页。

常用主线，选一种贯穿全篇：

| 主线 | 顺序 | 适合 |
|---|---|---|
| 背景—问题—方案 | 已知什么 → 缺什么 → 本工作补上什么 | 开题、论文报告 |
| 漏斗 | 大背景 → 具体缺口 → 方法 → 结果 → 意义 | 中期、答辩 |
| 结论先行 | 先给结论和进展，再给依据 | 阶段汇报、时间紧的场合 |
| 进展汇报 | 进展 → 证据 → 卡点 → 下一步 | 组会；卡点写清卡在哪、试过什么、需要导师给什么意见，不要只报喜 |

研究问题或本次目标最迟在第 2、3 页讲清楚。听众需要它来判断后面每一页。

**论文精读**按论文类型选主线，开头一句话说明类型（「这是一篇方法型论文」），让听众确认：

| 类型 | 主线 |
|---|---|
| 方法型（新算法、新结构、新器件设计） | 现有方法缺什么 → 核心思路 → 方法细节 → 对比实验 → 消融 → 适用范围和局限 |
| 实验发现型（测量、现象、规律） | 问题 → 假设 → 实验设计 → 关键证据（每页一张子图）→ 机制解释 → 证据边界 |
| 系统 / 工程型（平台、系统、数据集） | 需求 → 架构 → 关键模块 → 规模和性能 → 案例 → 不足 |
| 综述型 | 领域地图 → 分类框架 → 每类代表工作 → 对比表 → 开放问题 |

每类最后都加一页「对我们的启发」或「讨论问题」。讲论文的局限时要区分作者自己承认的和你的判断。

## 2. 结论句标题

每张内容页的标题是一句完整的话，说出这一页的结论，而不是主题词。

| 主题词（不要） | 结论句（要） |
|---|---|
| 对象的划分 | 课程知识只存一份，查询和问答都从它读取 |
| 关系类型 | 九种关系中七种有方向，方向由类型决定 |
| 数据校验 | 启动时 20 条规则逐项检查，错误定位到具体字段 |
| 检索效果 | BM25 检索的前 5 命中率达到 X（X 取自评测结果，不能估） |
| 后续计划 | 下一阶段先定技术选型，再做五项原型工作 |

- 长度一行以内，约 26 字。写不进一行，说明这一页的观点还不够集中。
- 有数字就写数字，「提高 3.4 倍」胜过「显著提高」。
- 只读标题测试：按顺序只读标题，应能把整份汇报讲完。

## 3. 证据

- **一页一个主证据**：一张图、一个表、一个流程或一组并列卡片。两个证据说两件事，就拆成两页。
- **证据要直接支撑标题**：遮住证据只读标题，标题仍然成立，说明证据可有可无；
  遮住标题只看证据，看不出结论，就要在证据上加标注。
- **在图上标出关键点**：用强调色、箭头或一行小注标出关键数据，不要让听众自己找。
- **趋势和对比用图，精确数值用表**。
- **论文里的图裁到要讲的那个子图**，不放整张多面板图（取法和裁切质检见 `references/figures.md`）。
- **放上去的证据都要讲到**，讲不到的移到备用页。

## 4. 文字

- 每页 ≤ 3 个核心信息，正文约 120 字以内（`qa_check.py` 超过 150 字报 ⚠️），超了就拆页。每条列表一个意思，3–5 条为宜。
- 用短句，可以省略「我们」「进行了」这类虚词：「启动时检查 20 条规则」而不是「我们在系统启动的时候对 20 条规则进行了检查」。
- 加粗只用于关键术语和行内标签（「产出：」「注意：」），强调色只用于关键结论。
- 不写套话：「值得注意的是」「综上所述」「总的来说」「具有重要意义」「不是……而是……」这类句式删掉，直接写判断。
  标题、正文和口播稿里每句话都要指向这份材料里具体的方法、数据或结论，放到任何汇报里都成立的句子要重写。

## 5. 引用

- 组会、课程汇报的页面上不写出处（见 SKILL.md 第 3 节），讲到别人的成果时口头说明出自哪篇论文、哪个团队。
- 需要参考文献页时（如正式答辩）放在最后，条目按 GB/T 7714-2015；网图的条目取 `.json` 里的 `reference`。

## 6. 时间与答问

- 约每分钟一页。超出时砍章节，不要压缩单页密度。
- 提前想好被问到最多的三个问题，把答案要用的图放进备用页。
- 结束停在总结或下一步那一页，让它在答问时留在屏幕上。
- 每页口播稿两三句，讲「这一页说明了什么、听众该记住什么」。
