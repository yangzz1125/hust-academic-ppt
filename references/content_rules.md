# 学术汇报的内容规范

写讲稿前读一遍。改已有 deck 时，把第 2–5 节当检查清单。

## 1. 论证主线

先确定整份汇报要让听众接受的那**一个**结论，其余内容都为它服务。讲不完的放进备注或备用页。

常用主线，选一种贯穿全篇：

| 主线 | 顺序 | 适合 |
|---|---|---|
| 背景—问题—方案 | 已知什么 → 缺什么 → 本工作补上什么 | 开题、论文报告 |
| 漏斗 | 大背景 → 具体缺口 → 方法 → 结果 → 意义 | 中期、答辩 |
| 结论先行 | 先给结论和进展，再给依据 | 阶段汇报、时间紧的场合 |
| 进展汇报 | 进展 → 证据 → 卡点 → 下一步 | 组会；卡点写清卡在哪、试过什么、需要导师给什么意见，不要只报喜 |

研究问题或本次目标最迟在第 2、3 页讲清楚。听众需要它来判断后面每一页。

**论文精读**按论文类型选主线，开头一句话说明类型（「这是一篇方法型论文」），让听众确认：

| 类型 | 主线 |
|---|---|
| 方法型（新算法、新结构、新器件设计） | 现有方法缺什么 → 核心思路 → 方法细节 → 对比实验 → 消融 → 适用范围和局限 |
| 实验发现型（测量、现象、规律） | 问题 → 假设 → 实验设计 → 关键证据（每页一张子图）→ 机制解释 → 证据边界 |
| 系统 / 工程型（平台、系统、数据集） | 需求 → 架构 → 关键模块 → 规模和性能 → 案例 → 不足 |
| 综述型 | 领域地图 → 分类框架 → 每类代表工作 → 对比表 → 开放问题 |

每类最后都加一页「对我们的启发」或「讨论问题」，里面的内容按第 5 节写成建议，不写成论文的结论。
讲论文的局限时要区分作者自己承认的和你的判断。

论文精读、文献汇报用**严格材料边界**（`outline.json` 的 `meta.strict`）：只读材料清单里写明的页和节，不全文扫描，
不检索清单以外的论文；资料和图都只从清单里的论文来，不画描述性插图，不编论文里没有的实验数据、参数或技术细节。
材料不够撑起某一页时，标成待核对，问用户要，不自己扩大阅读范围。

### 背景章：一步一页推出研究问题

用户指出过「背景经常讲不清楚」。对照用户认可的开题 PPT（张楠，低气压 CCP 智能诊断）：它的背景 4 页是一条推理链，
每页推进一步、页底一句「由此可见…」接到下一页；我们的答辩稿背景是「低温等离子体特点 → 全局模型 → 氧放电反应」三个知识点并排，
讲稿里有因果，页面上看不出来。背景章按下面几步推，一步一页（内容少的两步可以合一页）：

| 步 | 回答 | 那份开题 PPT 的写法 |
|---|---|---|
| 1 应用和需求 | 这件事为什么重要、谁在用、要求有多高 | 芯片无处不在 → 制造十几道工序里刻蚀、沉积靠等离子体 → 对精度、均匀性、重复性要求越来越高 |
| 2 对象和过程 | 研究对象是什么、怎么工作 | 干法与湿法刻蚀的电镜照片对比 + 刻蚀机理图 |
| 3 痛点和代价 | 哪里会出问题、出了问题付出什么代价、现在怎么应付 | 外部条件 → 内部状态 → 刻蚀质量三块串起来：工艺设定相同，状态仍会漂移，良率下降 |
| 4 切入点 | 有什么能测、能算、能利用 | 放电照片、光谱、V–I 波形：光电响应能非侵入地反映内部状态 |
| 5 研究问题 | 本工作要回答的那个问题 | 如何利用外部易获取的光、电信号快速准确诊断内部状态 |

- **要点句写这一步推出的结论**，不写这一页的知识点：「主导反应随气压改变，单一工况无法验证机理」，
  不写「O₂(a) 损失通道占比具有气压依赖性」。背景章的要点句连起来读，应该就是第 1 页到研究问题的推理。
- **页底一句接下一页**：`bottombar("由此可见", 一句话)`，说出这一页推出了什么、下一页要解决什么。它和要点句不重复：
  要点句是这一页的结论，页底这句是往下一页的推论（「缺乏在线监测，等于在内部状态未知时精密加工」）。
- **术语先介绍再用**：页面上出现的每个术语（全局模型、反应机理、O₂(a)），要么前面的页讲过，要么这一页配图讲清；
  听众是课程老师、答辩委员时，按「懂本学科、不懂本方向」估计。讲稿确认前逐页查一遍。
- **背景章的图最多**：每页 3–4 张以上，列举的每一项配一张图（`figures.md` 第 1 节）。
  步 3 这种因果关系用「因果链」页型（`layouts.md` 第 7 节）。

## 2. 讲稿

先写讲稿，再切页（用户明确要求过）：页和页之间的逻辑在讲稿里就连好，切页时不会割裂。

- **写成口语稿**：像要上台念的那样，一句接一句往下讲，不写提纲、不写要点列表。
  句子完整，带上「因为、所以、于是、但是」这类连接词，把原因和过程讲出来。
- **开头提出问题，结尾回答**：开头用一个让听众关心的问题（现象、矛盾、需求）开场；每章第一段点明它回答的是哪一部分
  （「先看第一个现象：为什么都是 2.45 GHz？」）；最后一段逐一回答。
- **段与段接上**：每段的第一句交代它和上一段的关系（「这 30 年里，核心一直是磁控管」「磁控管要靠直流高压驱动……」），
  这一句切页后就是这一页的过渡句。章末用一句话引出下一章。
- **一段讲一件事**：一段（或连着的一两段）之后会变成一页。一段里讲了两件事，切页时就拆成两页。
- **证据在讲稿里点名**：要给听众看的照片、公式、数字，讲稿里直接说出来（「我们对着照片上的编号……」「写成公式……」），
  切页时它们就是这一页的证据。
- **字数只作参考**：按每分钟约 200 字估算时长，讲得顺最要紧（用户明确说过），不为凑字数加句子，也不为压字数删掉因果。
- 讲稿里的每个数字都要能在材料里找到出处，和页面一样用 `qa_check.py --source` 核对。

## 3. 标题和要点句

**页面标题写主题词**（用户明确要求过：结论句太长）：说清这一页讲什么，16 字以内，一行放下。
**要点句**写在标题下的浅底条里（用户明确要求过），20 字以内，是讲稿里这一页几段的中心句：听众该记住的那一句话，
用书面语重写，不照抄讲稿的口语。

| 不要 | 标题（主题词） | 要点句 |
|---|---|---|
| 「研究内容」（太空，哪份汇报都能用） | 知识点之间的关系 | 九种关系中七种有方向，由类型决定 |
| 「课程知识只存一份，查询和问答都从它读取」（结论句，太长） | 课程知识的存储 | 课程知识单一存储，查询与问答共用 |
| 「结果」 | BM25 检索效果 | 前 5 命中率达到 X（X 取自评测结果，不能估） |
| 「后续计划」 | 下一阶段工作 | 先完成技术选型，再开展五项原型工作 |
| 「前两类已做成，只在定好的参数里找最优」（口语） | 实时控制与工艺优化 | 已实现前两类任务，在指定参数域内寻找全局最优 |

### 页面文字用书面语，讲稿用口语

用户明确要求过：页面上的表述不能口语化。**讲稿和口播稿**是要念出来的，照第 2 节写成口语；**页面上的文字**——
标题、要点句、正文、图注、面板结论、总结条——用简洁准确的书面语和本领域术语。切页时从讲稿提炼要点句和页面文字，
要改写，不照抄。`outline.py check`（标题、要点句）和 `qa_check.py`（页面全部文字）会按 `hust_deck.COLLOQUIAL`
提示常见口语说法。

| 口语（讲稿里可以） | 书面语（页面上） |
|---|---|
| 已经做成了 | 已实现 |
| 只在定好的参数里找最优 | 在指定参数域内寻找全局最优 |
| 写错一条，结果就对不上测量 | 单条反应有误即导致模拟与测量偏离 |
| 有的错只在个别气压下露头 | 部分错误仅在特定气压下显现 |
| 现在靠人一条条查 | 目前依赖人工逐条排查 |
| 调的参数 | 调节变量、优化变量 |
| 仿真里训练，换基底都控住温度 | 仿真训练后迁移至实验，多种基底下均实现温度控制 |
| 成本约降一半 | 达标成本降低约 50% |

书面语也要短：去掉「进行了……的研究」「实现了对……的有效控制」这类空动词和套话（第 5 节），一句只说一件事。

- 同一份汇报里标题的写法一致，都是名词短语，不夹带结论。章节标签只做导航，写章节名。
- 要点句有数字就写数字，「提高 3.4 倍」胜过「显著提高」。
- **按顺序读一遍**：`outline.py check` 和 `qa_check.py` 最后都会列出「标题 ｜ 要点句 ｜ 过渡句」，
  要点句连起来应能把整份汇报讲完，过渡句连起来应能看出每页是怎么接上一页的。

## 4. 证据

- **一页一个主证据**：一张图、一个表、一个流程或一组并列卡片。两个证据说两件事，就拆成两页。
- **证据要直接支撑要点句**：遮住证据只读要点句，要点句仍然成立，说明证据可有可无；
  只看证据看不出要点，就要在证据上加标注。
- **在图上标出关键点**：用强调色、箭头或一行小注标出关键数据，不要让听众自己找。
- **趋势和对比用图，精确数值用表**。
- **要对着讲的论文图裁到要讲的那个子图**，不放整张多面板图（取法和裁切质检见 `figures.md` 第 6 节）。
- **放上去的证据都要讲到**，讲不到的移到备用页。例外是讲文献时只作展示的原图（`figures.md` 第 1 节）：
  它们整组说明「这项工作做了什么」，口播讲这项工作，不逐张讲图。
- **每个数字、每张图都能找回原文**：资料要点写到文件名加页码或节号，有适用条件（工况、样本、设置）一起写；
  论文图写到 PDF 页码、图号和要保留的坐标轴、图例（`outline.md` 第 2 节 `research`、`figures`）。
  复核时照着出处直接翻到那一页，不用重新找。找不到依据的不猜，写进 `todo` 待核对。

## 5. 文字

- **内容要充实**（用户明确要求过）：一页一个结论，但证据写足。页面上的正文 100–200 字为宜，用完整句子写（`qa_check.py` 超过 280 字报 ⚠️），
  每张卡片 3–5 条，每条是一个具体的事实，不是一个词。卡片里出现大块空白就是内容不够，`qa_check.py` 会报出来。
  以图为主的页字可以少：图能证明要点句、图注和一两句解读把要点说清，就是充实的。
- **充实看信息量，不看字数**（用户明确指出过）：字数和卡片密度只是下限。主证据要能证明要点句——
  证明不了要点的外观照片只是摆设；只讲「是什么」不讲「怎么做到」的页，加多少条要点都还是薄。
  先查讲稿和提纲（SKILL.md 工作流第 2 步的提纲检查），合并重叠的段落，再按下面补内容。
- 内容不够时，从材料里按下面的顺序补，补的每一句都要能在材料里找到：
  1. **原因和机制**：为什么这样、背后的过程是什么（「网孔远小于波长，所以微波出不去」）。
  2. **具体数字**：参数、估算值、对比数据，写上单位和条件。
  3. **例子**：一个具体的实例、数据片段、报错示例、计算过程。
  4. **对比**：别的做法是什么、为什么不选，或者改进前后的差别。
  5. **边界和代价**：适用条件、局限、要付出的代价。
  材料里确实没有可补的，再缩小卡片、合并到别的页；不要用套话或重复标题来凑字。
- 句子要短，但要完整：主语、动作、结果都在，讲原因时带上连接词。「启动时逐条检查 20 条规则，出错就定位到字段」，
  不写「规则检查 / 字段定位」这种碎片短语，也不写「我们在系统启动的时候对 20 条规则进行了检查」这种拖沓的长句。
  并列的几项才用列表，图上的标注才用标签。
- **分开「论文的结论」和「对我们的建议」**：页面和讲稿里，论文明确写了的才说成结论（「作者在 4 次验证中偏差都在 3.5% 以内」）；
  推测性的解释、把几篇论文连起来的引申、对我们工作的建议，用「可考虑」「建议验证」「后续可探索」，
  不写成「论文表明」「已经证明」。版面上分开放：论文结论放在讲这篇论文的块里，建议放进单独一块
  （标签写「对我们的启发」或「建议」，`neutral` 灰色或主色浅底，不用强调色）或「对我们的启发」页。
  讲论文的局限时，作者自己承认的和你的判断也这样分开。
- 加粗只用于关键术语和行内标签（「产出：」「注意：」），强调色只用于关键结论。
- 不写套话：「值得注意的是」「综上所述」「总的来说」「具有重要意义」「不是……而是……」这类句式删掉，直接写判断。
  标题、正文和口播稿里每句话都要指向这份材料里具体的方法、数据或结论，放到任何汇报里都成立的句子要重写。

## 6. 引用

- 组会、课程汇报的页面上不写出处（见 `figures.md` 第 1 节），讲到别人的成果时口头说明出自哪篇论文、哪个团队。
- **开题、答辩：内容页只标「[n]」，全文统一放在末尾参考文献附录页**（用户明确要求过：页面空间不够）。
  - 讲到别人工作的地方标「[n]」：面板标签「贝叶斯优化 [7]」、图注或正文里。
  - 这一页引到的全文条目写在 `outline.json` 这一页的 `refs` 里，同一篇各页写成完全一样的条目；条目从报告的 `.bbl` 或
    `refs.bib` 取。编号按在本 PPT 中第一次出现的顺序，全份一致，`outline.py check` 会查编号是否从 [1] 连续、
    同一编号是否对应了两条条目。
  - 生成脚本最后调用 `deck.references(refs_in_order("outline.json"))`：12pt，条目多时自动分页。
- 条目按 GB/T 7714-2015；期刊、会议、学位论文有 DOI 的，条目末尾写上（「DOI: 10.1088/1361-6595/ab3c15.」），
  `check` 会提示缺的。网图的条目取 `.json` 里的 `reference`。

## 7. 时间与答问

- 约每分钟一页，页数由讲稿切出来。超时先删讲稿里的章节或段落，不要压缩单页密度。
- 提前想好被问到最多的三个问题，把答案要用的图放进备用页。
- 结束停在总结或下一步那一页，让它在答问时留在屏幕上。
- 口播稿就是讲稿里这一页的几段，不另写：第一句接上一页，中间讲这一页，最后一句引出下一页。
